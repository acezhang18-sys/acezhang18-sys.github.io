Knowledge Documentation

Overview

I treat documentation as a transfer tool, not as a archive of what I already know. If a capable person cannot pick it up and run the next step without a private briefing, it is still folklore. The work is turning lived judgment into something another person can use under load.

Core Method

  • Write for the next operator, not for my own memory
  • Capture the decision rule, not only the procedure
  • Keep artifacts short enough to be used in the moment
  • Update from live misses the same day they appear
  • Kill documents that only make sense if I am in the room to interpret them

Relevant Experience

  • Pre-Selection — Turned field lessons into published guides so aspirants and civilian staff were not stuck waiting for a voice channel. The guides made the path visible. Shadowing and mentorship still transferred leadership. Documentation made the reps available when I was not.
  • ASVAB and accession prep — Logged weak sections, timing failures, and repeatable mistakes from diagnostic sessions. The notes became a reusable map instead of a one-time explanation.
  • Team Echoes — Led by example and let apprentices shadow the work. Documentation and infrastructure access made handoff a matter of passing real pieces of the system to people who had already watched the ordinary runs, not a binder they had never seen.
  • 38th and similar units — After-action notes and standards writeups turned quiet moves into transferable judgment. Hidden purpose was written down after the fact so observation did not die as “you had to be there.”
  • Performance transfer — Recurring patterns from sales floors, staff rooms, and high-rejection environments were written as short loops other people could rerun alone.

Method

What gets written
  • The outcome in one line
  • The few steps that actually produce it
  • The failure modes that keep showing up
  • How you know it worked

What does not get written
  • Theory that does not change the next action
  • Personal mythology
  • Instructions that require my tone of voice to decode

How it stays alive
  • Capture the same day as the lesson
  • Put the artifact where the work happens
  • Revise it when someone follows it and still fails
  • Hand the document to someone else and watch where they stall

What This Means for Clients / Collaborators

I can take knowledge that currently lives in one person’s head and turn it into short, usable artifacts: guides, checklists, decision maps, and after-action notes. The test is simple. A competent stranger should be able to run the next step without a private call.
